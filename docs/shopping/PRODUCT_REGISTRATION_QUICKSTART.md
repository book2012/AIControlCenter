# 상품 등록 빠른 시작

Status: 운영 입력 표준 적용. 신규 범용 WooCommerce 등록 자동화는 별도 구현 과제이며 현재 미구현.

## 다음 등록부터 보내는 내용

상품 사진을 함께 올리고 아래 블록을 채워 주세요. 모르는 항목은 비워두거나 `확인 필요`라고 적으면 됩니다. 사진은 여러 장을 한 번에 첨부하고, 같은 상품의 사진이면 한 상품으로 묶습니다.

```text
상품명/브랜드: (모르면 사진으로 확인)
판매가: (원화 금액 또는 조사 요청)
색상:
사이즈:
옵션별 실제 재고: (색상·사이즈별 수량, 모르면 확인 필요)
상품 상태: (새상품/중고 및 사용감)
포함 구성품:
상품 설명에서 강조할 점:
이미지 요청: (누끼 / 정면 참고 / 디테일 / 착용 참고, 기본은 상품 특징 보존)
기타:
```

최소 접수 조건은 상품 사진과 판매가입니다. 옵션·재고를 모르면 0개 및 판매 대기로 남기고, 재고가 확인되기 전에는 주문 가능 상태로 바꾸지 않습니다. 가격·재고는 이미지나 웹 검색으로 추측하지 않습니다.

## 처리 순서

1. **접수 묶기** — 첨부 사진을 상품별로 묶고 중복·다른 상품이 섞였는지 확인합니다. 식별 가능한 브랜드·모델·카테고리만 초안으로 잡습니다.
2. **정보 보완** — 사용자가 요청한 경우 공식 브랜드/판매처 자료를 우선 확인합니다. 검색으로 확인한 사실과 사진에서 관찰한 특징을 구분해 상품명·설명·태그 초안을 씁니다. 품번, 소재 혼용률, 치수, 정품 여부는 신뢰 가능한 근거가 없으면 확인 필요로 둡니다.
3. **이미지 준비** — 원본은 보존합니다. 썸네일/상세 이미지는 상품의 색상·실루엣·디테일을 임의로 바꾸지 않습니다. 생성한 착용·정면 참고 이미지는 실물 촬영 사진처럼 표현하지 않고 AI 참고 이미지로 표시합니다. 원본과 결과 이미지의 연결 및 SHA-256 manifest를 확인합니다.
4. **한 번에 검토** — 등록 전에 다음 요약을 한 카드로 보여줍니다: 상품명·분류, 판매가, 색상/사이즈별 재고, 확인된 사실/확인 필요 항목, 사용할 이미지 목록과 AI 생성 이미지 표시, 공개 범위(DEV). 틀린 항목만 고치면 되도록 작성합니다.
5. **DEV 등록 및 확인** — 검토된 값으로 DEV에만 등록합니다. 등록 후 상품 페이지, 이미지 로딩, 가격, 옵션, 재고, 주문 가능 여부를 다시 읽어 확인합니다. PROD 등록·변경은 이 절차에 포함되지 않습니다.

## 등록 전 필수 확인

- 판매가는 사용자가 지정했거나 사용자가 조사·제안 가격을 명시적으로 요청한 값이어야 합니다. 조사 가격은 제안값으로 표시하고 확정 전 등록하지 않습니다.
- 주문 가능 상태에는 실제 색상/사이즈 옵션과 확인된 재고가 필요합니다. 미확인 재고는 0으로 유지합니다.
- 상품 설명에 사진으로 알 수 없는 소재, 품번, 정품 여부, 측정값을 사실처럼 쓰지 않습니다.
- 색상과 사이즈 조합, 옵션별 재고 합계, 가격, 대표 이미지, 상세 이미지가 서로 맞는지 확인합니다.
- 이미지 생성/보정으로 바뀐 요소와 실물 차이가 있을 수 있는 부분을 미리 밝힙니다.
- 최종 요약에서 상품명, 가격, 옵션/재고, 이미지에 대한 수정 지시를 한 번에 받아 반영합니다.

## 현재 DEV 도구의 경계

- `dev_product_operator.py`는 이미 등록된 상품의 가격·재고·공개 상태 변경과 조회용입니다. 신규 상품 생성 명령은 지원하지 않습니다.
- `dev_upload_product_stage.py`와 `dev_upload_product_promote.py`는 특정 상품 ID와 값에 고정된 단일 상품 도구입니다. 새 상품에 그대로 재사용하면 안 됩니다.
- `dev_upload_batch_register.py`는 별도로 검토된 17개 대기 재고 항목에만 묶여 있습니다. 새 단일 상품 등록 도구가 아닙니다.
- 범용 ProductDraft 흐름은 설계/도메인 검증이 있지만, 사용자 입력부터 WooCommerce 등록까지 연결하는 런타임은 아직 구현되지 않았습니다.

따라서 새 상품 요청이 오면 이 문서의 접수·검토 포맷을 사용하되, 실제 등록 실행은 해당 상품에 맞춘 DEV 범위와 검증이 준비된 뒤 진행합니다. 기존 고정 스크립트에 상품 데이터만 바꿔 끼우지 않습니다.

## 다음 자동화 과제

범용 단일 상품 등록기를 만들 때 아래 계약을 기본값으로 적용합니다.

- JSON 입력 및 JSON 결과, 기본 실행은 읽기 전용 `plan`.
- 입력값/이미지 manifest/중복 SKU/옵션·재고 합계를 먼저 검사.
- 같은 입력의 반복 실행은 중복 상품을 만들지 않는 idempotency.
- `--apply-dev`만 격리된 DEV WooCommerce에 쓰고 PROD·Ubuntu를 접근하지 않음.
- 등록 후 WooCommerce를 다시 읽어 가격·이미지 해시·변형·재고를 검증.
- 사용자 확인 전 재고 미확정 상품은 비판매 상태로 유지.

이 자동화가 구현되면 상품별 예외 스크립트 대신 이 등록기로 신규 상품을 처리합니다.
