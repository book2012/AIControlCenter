# SHOP_AI_001C-C5-C3C-H1 — Authority Live-Read Hardening

## Status

Offline authority hardening only.

This stage does not activate Twilio networking, real credential
resolution, macOS Keychain access, SMS delivery, deployment, or
Ubuntu authority.

## Control-plane ownership

AIControlCenter on the Mac remains the sole trusted control plane.

The generic C5-B provider network authorization model remains
`OFFLINE_DENY_ONLY`.

The Twilio-specific C5-C3A authority remains the sole issuer and
one-shot verifier for trusted authenticated-read capabilities.

## Registry lifecycle

`TwilioAuthenticatedReadAuthority` uses a bounded in-memory
registry.

A capability record is retained through:

1. its normal capability TTL; and
2. one additional bounded retention window equal to
   `MAX_CAPABILITY_TTL_SECONDS`.

After that retention boundary the authority removes the capability
from both `_issued` and `_used`.

Pruning occurs only during normal authority operations and creates
no timer, thread, scheduler, database state, or external dependency.

Within the retention window, existing reason semantics remain
available:

- first successful trusted attempt -> `AUTHORIZED`
- repeated trusted attempt -> `CAPABILITY_ALREADY_USED`
- first attempt after expiry -> `CAPABILITY_EXPIRED`

After the retention boundary, trust metadata is intentionally
forgotten and the old capability is treated as
`CAPABILITY_UNTRUSTED`.

This is deliberate: the always-on control plane must not retain
capability objects indefinitely.

## Issuance identifier collision

`issuance_id` remains opaque and generated by the existing default
`secrets.token_hex(16)` factory.

The authority rejects an issuance identifier that collides with any
currently retained capability record.

Collision handling is fail-closed and issues no second capability.

The authority intentionally does not maintain an unbounded
historical issuance-ID set. Collision protection therefore covers
the bounded retained authority window.

## Preserved invariants

- maximum capability TTL remains 60 seconds
- authorization remains one-shot
- the first trusted authorization attempt consumes the capability
- provider binding remains `twilio.verify.v2`
- only `READ_HEALTH` and `READ_EVIDENCE` are eligible
- C5-C3C0 remains authorization-first
- provider HTTP remains GET-only
- maximum provider transport attempts remains one
- retry remains disabled
- fallback remains disabled
- real credentials are not resolved
- macOS Keychain is not accessed
- provider networking is not performed
- SMS is not sent
- C4 remains the sole durable reconciliation writer
- Ubuntu has no control-plane or credential authority

## Live boundary

This hardening stage does not authorize live Twilio access.

Real macOS secret resolution and an authenticated allowlisted
non-production Twilio GET remain a separately explicit
approval-gated stage.
