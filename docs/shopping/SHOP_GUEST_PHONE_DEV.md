# DEV guest phone verification

AIControlCenter owns guest phone authority; no customer username or password is required. This explicitly authorized DEV composition uses Twilio Verify for exactly one configured test phone. It does not activate production phone auth or reuse prior read-only Twilio authority for writes. The guest customer/contact IDs are independently allocated opaque identifiers, privately persisted and separate from the synthetic test account.

The existing PhoneVerificationService durably owns challenge/provider receipt policy. A separate private DEV browser bridge commits start/check ownership before external calls, binds a Secure HttpOnly SameSite=Strict cookie to challenge/replay, checks origin and consent, bounds request bodies and scopes sends to the fixed normalized number. Starts are limited to three/hour, with a 60-second cooldown and no overlapping active request. Replays with the same browser cookie do not resend. Unknown start/check ownership is not auto-retried. Incorrect codes end the current check; no blind retries are offered.

The replaceable DEV port uses verified HTTPS, fixed Twilio Verify endpoints, no redirects or environment proxy, bounded response parsing and matching account/service/destination/channel/provider verification SID. Only approved provider evidence yields a trusted receipt. A pending customer is marked verified only after successful evidence, and the existing customer-session route consumes that durable receipt to issue the normal Secure HttpOnly customer cookie. No OTP, phone or credential enters cart storage or public models. This one-number mapping is DEV-only and must not be promoted as a multi-customer production identity repository.

The guest chat shows SMS consent, number and code input. No automatic SMS is sent merely by opening checkout. Phone code and number are cleared after use. Shipping capture and final order confirmation remain disabled; guest sessions cannot pass the existing synthetic customer-only Woo writer policy.
