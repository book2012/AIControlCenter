# M3-A4B2B2B Activation Authorization Checklist

Recovery-2 evidence is not activation authorization. Fresh independent
approval must bind the final clean synchronized R3 commit.

R3 composes authorization only through the dedicated live coordinator. It did
not create a real authorization; fresh approval is required for its commit.

- Confirm feature branch, exact commit, clean tree and upstream parity.
- Bind the human approval report and permit issuance review by ID and digest.
- Record requester, Mac operator and independent approver; do not invent identities.
- Confirm operator and approver are distinct.
- Bind every active restriction and both required acknowledgements.
- Bind the approved shared-parent policy and exact absent managed target.
- Bind runtime plan, schemas, test evidence and an all-zero safety snapshot.
- Set an explicit approval time, not-before time and expiry.
- Require controlled non-production scope and maximum uses equal to one.
- Keep writers, monitoring, external dispatch and production authorization false.
- Reject synthetic authorization for non-synthetic issuance.
- Obtain fresh independent approval after any bound commit changes.

Completion of this checklist does not itself authorize production or execute
the bootstrap.

R4 compatibility does not create authorization. Confirm the strict preflight
contains exact Boolean `ubuntu_participation=false`, confirm no other Ubuntu or
generic runtime field exists, and confirm the permit boundary is the immutable
typed contract rather than a mapping. A fresh independent approval must bind
the R4 commit; production remains `NOT_AUTHORIZED`.
